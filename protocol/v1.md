# Fengzhu Bridge Protocol v1

All authenticated HTTP calls use `Authorization: Bearer <access-token>`. WebSocket authentication uses the same header and never a query parameter.

Encrypted payloads use XChaCha20-Poly1305. The associated data is `v1|kind|threadId|eventId`. Frames contain only routing metadata plus `nonce` and `ciphertext` in base64.

## Authentication

1. `POST /api/v1/auth/challenge` returns a random nonce, account salt, and PBKDF2 iteration count.
2. The client derives the account key with PBKDF2-HMAC-SHA256 and sends `HMAC(accountKey, challengeId || nonce)` to `/auth/login`.
3. The server stores the derived verifier, never the password. A database leak permits an offline password attack, so a strong passphrase is mandatory.
4. Access tokens last 15 minutes. Rotating refresh tokens are device-bound and stored hashed.

## WebSocket frames

```json
{
  "id": "uuid",
  "kind": "command|event|approval.resolve|ack",
  "sourceDeviceId": "uuid",
  "targetDeviceId": "uuid-or-null",
  "threadId": "opaque-thread-id",
  "nonce": "base64",
  "ciphertext": "base64",
  "createdAt": 0
}
```

The relay assigns a monotonically increasing sequence. Reconnect uses `GET /events?after=<sequence>`. Ephemeral presence frames such as `thread.status.snapshot` are not persisted and use sequence `0`.

## Same-task follow-ups

- `followup.enqueue` persists a normal message in the Windows connector and queues it in the matching Codex Desktop task.
- `followup.list` returns the ordered queue; `followup.cancel` removes an item that has not started.
- Connector events are `followup.snapshot`, `followup.queued`, `followup.started`, `followup.cancelled`, and `followup.failed`.
- Each request carries a unique `requestId`. An uncertain desktop delivery is never retried automatically.

## Active-turn steering

- `turn.steer` targets the active turn of the original task through the desktop adapter.
- `steer.accepted` confirms native Codex Desktop acceptance.
- `steer.deferred` means the instruction was retained as a same-task follow-up because the active phase could not accept steering.
- `steer.uncertain` requires confirmation on the computer and must not trigger an automatic resend.
- Automatic `thread/fork` is forbidden in both follow-up and steering fallback paths.

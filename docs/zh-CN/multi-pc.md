# 一个账号，多台电脑

2026-10-25 起（服务器 v2-session、桌面 0.1.21、连接器 0.2.96、Android 0.1.264），同一个 khLink 账号可以在多台 Windows 电脑上登录，一部手机同时看到并切换这些电脑，各自的会话不混在一起。

## 原来卡在哪里

服务器早就允许一个账号有多台桌面/连接器，帧按 `targetDeviceId` 路由，历史表也记 `connector_id`。真正的障碍是**加密密钥**：每台电脑安装时随机生成自己的账户密钥（`kh-link-desktop/src-tauri/src/lib.rs` `Identity::generate`），手机只存一把。第二台电脑的帧和历史手机全都解不开，等于看不见。

## 现在的做法：所有电脑共用一把账户密钥

1. 新电脑登录 khLink 账号（`/api/v2/session/oauth/complete`）。服务器发现这个账号已经有别的（未撤销）桌面或连接器，而这台电脑没有拿过密钥，就把它的 `key_envelope` 记为 `pending` 并在响应里返回 `keyPending: true`。同一台电脑再次登录、已经拿到密钥的电脑都不会再 pending。
2. 在线的连接器本来就每 10 秒问一次 `/connector/devices/pending-keys`（给手机发密钥用）。现在这个列表也包含 pending 的电脑（不含调用者自己的桌面），连接器用 device-key v3（X25519 + XChaCha20-Poly1305，AAD 绑定账号和设备 id）把自己的账户密钥包给新电脑的公钥，`POST /connector/devices/key`。只有 pending 的电脑能被写入，已有密钥的电脑不会被别的连接器覆盖。
3. 新电脑轮询 `GET /session/key-envelope`（现在桌面也能调），用自己的私钥解开，换掉本机生成的账户密钥，**然后**才开通自己的连接器。登录时最多等 90 秒；还没拿到就在界面提示“请保持另一台电脑上的 khLink 在线”，之后每 15 秒自动再试一次（`awaiting_shared_key` 记在本机加密存储里）。
4. 手机不用改：一把密钥解所有电脑。

前提：第二台电脑登录时，至少有一台已有密钥的电脑的连接器在线。

## 连接器

`onFrame` 收到 `targetDeviceId` 不是自己的命令帧时直接跳过（只推进序号）；没有目标的旧手机帧照常处理。

## 手机

- 首页标题下有电脑切换条（账号有两台以上电脑时才显示）：每台电脑一个标签，绿点表示 45 秒内有心跳。点哪台，列表就只显示哪台的会话；新建任务也发到这台。
- 通知或新建的会话属于另一台电脑时，自动切到那台再打开。
- 每台电脑的心跳分开记；**别的电脑**发来的 `connector.offline`、电脑负载、Claude/DSH/Codex 用量、账号状态不再覆盖当前电脑的显示；`followup.snapshot` 只替换发来那台电脑的会话的排队项。
- 切换电脑时清掉上一台的负载、DSH/Hermes 模型目录，并重新读取能力和排队。

## 已知边界

- 第一台电脑之前已经单独装过、各自有密钥的第二台电脑（2026-10-25 之前登录的）不会自动改用共享密钥；需要在那台电脑上撤销后重新登录。
- 同一个 Hermes/DSH 会话 id 若出现在两台电脑上，历史表的 `connector_id` 会被最后上传的那台改写（本次没有遇到）。

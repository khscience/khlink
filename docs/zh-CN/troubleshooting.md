## 手机更新提示重复按钮

Android 0.1.243 修复下载界面重复出现两个“取消下载”的问题。更新、下载、完成和失败各自显示对应按钮，操作不再混在提示文字里。详情见[应用内更新](android-app-updates.md)。旧版本下载本次升级时仍使用旧弹窗；安装新版后，后续更新使用新界面。

## 手机上显示电脑离线

1. 在电脑上确认连接器在运行：桌面控制台首页会显示后台是否在运行；也可以运行 `schtasks /Query /TN FengzhuAgentBridge` 查看计划任务状态。
2. 用 `node fengzhu-connect/src/cli.js doctor` 检查连接器配置和到中转的连通性，`server` 应为 200。
3. 连接器日志在 `%APPDATA%\FengzhuAgentBridge\logs`，看最后几行有没有连接中转失败的记录。
4. 自己部署中转时，确认手机和连接器填的是同一个地址（含路径前缀），并且是 HTTPS。
5. 分享日志前删掉其中的令牌、密码和本机路径。

## KH Link 反重力窗口连接

反重力使用电脑上的应用窗口同步与发送消息。原来的官方网页备用入口已移除。

- 首次使用：在电脑上打开反重力，确认对话能正常使用；手机等待连接器同步列表。
- 主界面文字发送仍依赖电脑上的反重力窗口。电脑有未发出的草稿时会拒绝覆盖；运行中或等待用户处理时，新指令会排队。
- 「发送中」表示连接器正在处理；「需确认」表示尚未找到该对话的新消息回执。保留内容，在电脑上检查对话，避免自行重复发送。迟到的记录同步后会自动更新结果。
- 重新连接或重启连接器时，同一个请求不会再次点击发送按钮。图片、文件与其他暂不支持的操作请在电脑端继续。
- 等待回答时也可以点「停止」取消原生问卷；取消后不会因旧数据库快照再次显示该问题。「重新同步对话」会重新读取当前会话历史。

## 发送与排队恢复

连接器 0.2.88 修复 Claude 桌面控制组件在部分 Windows 运行环境中初始化失败的问题。旧版在每次发送、新建任务或回答问题时临时编译系统调用组件，可能在点击发送之前报“客户端没有所需的特权”，手机却显示“发送结果尚未确认”。新版随包提供预编译组件并校验摘要；明确发生在发送前的初始化失败会显示“消息尚未发送”，不再作为未知回执处理。仍无法确定是否已经点击发送的超时会继续保留“需确认”，不会自动重发。

遇到之前留下的“需确认”，先核对那条对话的实际内容，再决定是否重新发送。更新不会自动重发旧消息，也不会为排查发送问题读取登录凭据。

Android 0.1.204 / 连接器 0.2.52 起，Codex 的桌面任务文字和图片使用协议队列传递；连接器先核对自己的协议进程是否持有该任务，避免把自己的任务锁误当成桌面窗口的锁。只读检查超时会保留消息等待重试，不表示已经发送。

「需确认」表示消息写入或点击发送后，尚未取得有效回执。连接器只核对真实队列和对话历史，不自动再次写入；迟到的回执确认后会清除提示。Codex 队列的请求编号用于核对回执，本身不保证去重。手机同一请求只提醒一次；首页或其他对话的后台回执不会反复弹窗。

Claude、Pi 的发送回执保存在电脑上，并与请求编号和内容绑定。手机或连接器重连不会把尚未确认的旧请求重新发送；重复的短句也只会由发送之后的新用户消息确认。

Pi 原生停止会清空整个原生待发队列。没有新用户消息证明已经送出的内容会保留为「需确认」；检查对话后可以复制内容或关闭提示。关闭提示不会发送消息。出现「失败」或「需确认」时先检查当前对话，避免重复执行同一指令。


## KH Link 的 Claude 额度停更或与桌面不一致

Claude 桌面版的本地用量样本不保证持续更新。本机 2.26454.2 的配置要求最近 24 小时打开过系统托盘的用量弹窗；电脑锁屏或系统闲置超过 10 分钟时也会暂停轮询，即使后台任务还在运行。只打开「设置 → 用量」不一定恢复这份本地样本。

- 手机中的「数据更新于」是原始样本/额度事件的时间，不是连接或刷新按钮的时间。
- 超过 30 分钟的数据只显示「历史剩余」，额度条不把它作为当前余额填充。即使 Code 没有新对话记录，也可能在网页或 Cowork 中用了额度，因此不会因为 Code 闲置就把旧数字当成当前值。
- 在电脑的系统托盘里点击 Claude 图标，打开其用量弹窗；Claude 写出新样本后，KH Link 会自动同步。手机刷新未拿到新数据时，会停止等待并显示说明。
- 5 小时/本周分别按各自的采样时间判断。百分比采用较新官方记录；同一组织、同一窗口仍有效的精确重置时间可沿用。当前账号超过旧重置点而没有新记录时，显示待更新；账号面板中的非活动账号仅可显示「预计剩余 100% / 待官方确认」，不把估算当作实时数据，不推算下一周期。
- 官方 Desktop 的本地 usage 响应缓存也是被动来源。KH Link 只取额度字段及原始响应时间，不读取 Cookie、Authorization 或登录凭据，不请求 claude.ai。两个来源都停止更新时，只能显示历史数字和日期。
- **2026-10-15 起所有安装都禁止主动额度探针**，包括未接管多账号的普通安装。手机「刷新额度」只是重读本地数据；即使官方命令行已登录且账号一致，也不会替用户发送任何模型消息来查额度。

历史值展示始于 Android 0.1.203 / 连接器 0.2.51；2026-10-15 的被动读取与账号切换修订以 [手机账号方案](mobile-account-switch.md) 最新进度为准。数据无法确认时，不能用历史值承诺当前额度。

## Claude 账号切换已暂时关闭（2026-10-18 起）

桌面 0.1.18、连接器 0.2.75、Android 0.1.226 起，Claude Desktop 账号切换已暂停：桌面左侧不再有「Claude 切换」，连接器对 Claude 的账号读取/切换请求返回关闭或拒绝，手机 Claude 页不再显示账号按钮和额度卡。`G:\Apps\ClaudeSwitch` 下的账号目录、额度样本、切换脚本和登记记录都保留，不需要清理。想恢复使用前，先读 `claude-code-backend-plan.md` §28 的条款复核和恢复条件，不要直接改 `features.js` 或连接器常量后上线。

## Claude 账号切换被拒绝或中断

- 手机账号条与电脑账号页共用同一操作状态。Codex 本期只读，手机对话仍属于默认账号。
- 运行中、等待回答/审批、排队消息、未生效设置、正在执行的手机操作均阻止切换。尚未验证不同版本定时规则，存在已启用定时任务时也先拒绝，请在官方 Claude 暂停后重试。状态读取失败、日志不明或有无法归属的辅助进程时，不推断为空闲。
- 锁屏、确认弹窗、版本变化或退出菜单不能唯一识别时停止。不会强制结束进程。切换期间发送不可用，草稿保留。
- 浏览器的 Claude 扩展也可能占用账号目录。2.37337.1.0 实测 `chrome-native-host.exe` 在 Desktop 正常退出后仍存活；现在切换前会提示保存工作并正常退出相关浏览器，不会自动关浏览器或强杀扩展。若已退出 Desktop 但辅助进程未退，账号链接保持原样，可从手机选择「重新打开 Claude」。
- `G:\Apps\ClaudeSwitch\shared` 下的 `desktop-switch.lock`、`switch.lock`、`desktop-operation-*` 记录进程与时间；`operations/` 保存请求编号和阶段。不要手动删除仍由存活进程持有的锁。组件超时会保留锁，直到确认组件退出。
- 中断后先核对目录链接。链接一致且旧进程已退出时，下一次操作可回收过期锁；链接事务不完整时保留锁，手机/桌面显示恢复入口。恢复要求官方 Claude 及其辅助进程全部退出，只恢复已登记的原链接，不复制登录文件；未知链接需在电脑检查，不提供强行绕过。
- 目标启动失败可「重新打开 Claude」或「切回原账号」。用同一请求编号重试不会重复执行已经落盘的操作；不要因为连接中断反复发起不同请求。

## Codex 非阻塞式回答短暂显示待发送

0.2.70 修复了结构化回答入队后找不到“引导”及额外误扫队列行的问题。手机显示“仍在电脑队列中”时，回答尚未进入当前任务，不能把它当成已回答；系统只等待/重试原队列行，不再提交正文。请不要另外复制重发。结果不确定时先核对电脑对话，再处理该条待发送记录。阻塞式问题则走原 app-server RPC，等待它确认；已失效或另一设备已回答会明确提示。完整区别与实测见 `seamless-switch-and-codex-input.md`。

## DeepSeek Harness 页没有会话或一直灰色

- 确认电脑上 DSH 桌面端正在运行；DSH 页只显示桌面 Host 的会话，不会另起 Web 进程。
- 检查 `%LOCALAPPDATA%\KH Link\dsh-desktop-bridge.json` 是否存在，`updatedAt` 是否在 1 分钟内，`port`/`pid` 是否对应正在运行的 `DeepSeek Harness.exe`。
- 若文件不存在，检查 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` 是否有 `kh-link-dsh-bridge` 行，以及
  `%USERPROFILE%\.dsh\profiles\node_modules\kh-link-dsh-bridge` 是否存在；重启连接器会重新安装。DSH 运行中通常几秒内热挂载，没运行则下次启动生效。
- DSH 重启后启动令牌会变；桥接插件会刷新文件，连接器下一次轮询会重新 `/connect`。仍 401 时重启 DSH 桌面端。
- 不要把该 JSON 发给别人：其中的 URL 等同于本机 DSH 的操作权限。连接器不会把令牌写日志或上传。

## DSH 页没有余额或今日花费

- 余额来自 DSH 的 DeepSeek Platform 登录状态；未登录或 `account/getBalance` 失败时显示“—”，不影响会话。
- 今日花费按钱包余额差计算：连接器跨天运行时会使用前一天最后一次余额作为今天起点；当天首次启动则显示“自 HH:mm”，只统计启动后的花费。充值会让差额变小，显示为 0。
- 今日花费是人民币，不再显示 token；模型切换在会话顶部“DeepSeek · 模型”里。

## DSH 置顶没有显示

- 连接器读取 `%USERPROFILE%\.dsh\storages\workspace.json` 的 `pinnedSessionIds`。确认 DSH 桌面端已置顶且该文件里的 id 是 `session-...`。
- 手机 DSH 页顶部的“置顶”分组会按该顺序显示；长按行可置顶/取消置顶，写回同一份 workspace 登记。
- 如果 DSH 换了 profile 或把 `DSH_HOME` 指到别处，连接器读的仍是 `~/.dsh`；需要设置 `DSH_HOME` 或手动把桥接/置顶文件放到对应目录。

## DSH 会话里的命令全部失败（0xC0000142）

这是 DSH 桌面端自身的进程创建问题，不是 KH Link 的发送失败：手机上的用户消息和回复仍会正常同步。错误码 `0xC0000142` = `STATUS_DLL_INIT_FAILED`，DSH 建议重启桌面端/桌面会话。重启后再从手机继续发即可，不需要重新配对。

## DSH 问题/审批手机怎么回答

DSH 的阻塞式 `ask_user_question` 和审批没有公开的远程回答通道；KH Link 用 UI Automation 读取并点按已经打开的 DSH 桌面窗口：

1. 保持 DSH 窗口打开并放在最前；
2. 在 DSH 会话顶部点“回答”；
3. 选 Red/Blue、允许一次/拒绝等选项，手机会直接点按 DSH 卡片。

限制：只支持当前会话的**单题选项**和审批按钮；自定义文字答案、多题分页、多选仍需在桌面完成。DSH 最小化或窗口被其他应用完全遮住时可能读不到，先把 DSH 切到前台。

## DSH 发图片报“模型不支持图片”

DSH 的 `deepseek-v4-pro` 不接受图片输入，`deepseek-flash` 接受。手机现在会显示 DSH 的原始错误（`Model "…" does not support image input.`），不再标成“发送结果尚未确认”。在会话顶部把模型切到 Flash 后再发图片即可。

## 回复里出现一大片空白

回复中的 markdown 图片如果指向电脑工作区的本地路径（如 `releases/xxx.png`），手机无法直接加载。旧版会给这种图片保留一个很高的空块；0.1.236 起改成单行可点击的 `🖼 文件名` 链接，点开时再向电脑取文件。远程 `http(s)` 图片保持原样。

## 电脑文件在手机里打开

0.1.238 起，电脑文件查看器支持：

- 图片：PNG/JPEG/GIF/WebP/BMP/HEIC/HEIF/AVIF/SVG，可双指缩放；
- 视频：MP4/M4V/MOV/WEBM/MKV/AVI/3GP，按原始比例在 khLink 内播放，轻点暂停/继续；
- Markdown/HTML/文本：预览或源码。

文件会先从电脑取回到手机（取回的文件在“电脑取回的文件”里），再在 khLink 内打开。视频编码是否支持取决于手机解码器；不支持的会提示保存或外部打开。

## App 内更新

App 启动时和使用过程中每 10 分钟检查一次更新。发现新版本弹窗提供：

- **立即更新**：App 内下载并校验，完成后交给 Android 安装；
- **推迟**：本次运行不再提示，下次打开再提醒；
- **本版本不更新**：忽略这个版本号；下一个更高版本仍会提示。

“本版本不更新”会持久保存，“推迟”只在当前进程内生效。Android 0.1.247 起，这些选择只影响自动提示；设置里的“检查更新”仍能找到同一新版。旧版点过推迟后误报“当前已是最新版”，可通过[官网下载安装包](https://khsci.com/khlink/download)覆盖升级，无需卸载或重新配对。

## Claude 页出现桌面没有的旧会话

Claude 页同时包含桌面 Claude Code 会话和手机创建的会话。旧版只清理“桌面上已消失的 desktop 会话”，手机创建的会话会一直保留。

0.2.87 起，手机创建的 Claude 会话如果同时满足：桌面没有对应会话、未置顶、不在运行/等待、超过 7 天没有活动，会自动归档（不删除 transcript）。因此升级后第一次同步可能会看到少量旧测试会话从列表消失。

# khLink 手机更新

## 下载源

Android 0.1.298 起，更新包优先从独立的公开分发仓库下载，顺序如下：

1. jsDelivr 的 Gcore 线路（文件不超过 20 MiB 时提供）；
2. GitHub Releases（`khscience/khlink-releases`）；
3. jsDelivr 的 Fastly、默认线路（文件不超过 20 MiB 时提供）；
4. khLink 服务器（`https://khsci.vip/fengzhu-bridge/downloads`），作为兜底。

- 检查更新时，手机同时向这些地方请求小型更新清单，只认签名校验通过的那份，几份都通过时用版本最新的。并查服务器清单是为了防止 CDN 缓存旧版本；它的流量远小于安装包。服务器先答复后，外部源各有短暂等待时间。
- 下载时按上面的顺序换源，下载完要核对清单里的 SHA-256，对不上不会安装。
- 下载源写在 `android/khlink-official.properties` 的 `updateMirrors`（逗号分隔），khLink 服务器总是最后一个。清空 `updateMirrors` 就只用服务器。
- 发布脚本 `ops/publish-release.sh` 先创建并校验 GitHub Release 草稿，把符合大小限制的包和签名清单推到 `dist`，再正式发布并更新服务器清单。外部发布失败会中止；只有明确指定 `--no-github` 才单独使用服务器。分发仓库只放已发布安装包和清单，源码仓库继续保持私有。
- 各地网络可能屏蔽不同域名，Gcore / Fastly / 默认线路并不保证同时可用，失败时按清单依次切换。所有包都要验证 SHA-256。

电脑端从 0.1.27 起也检查公开 GitHub 和 Gcore 的清单；连接器小包先走外部地址。完整 Windows 安装包超过 jsDelivr 单文件大小限制，因此使用 GitHub，连不上时由服务器兜底。

## 更新提示

Android 0.1.243 起，更新提示按当前步骤显示操作，所有操作都使用有边框或底色的按钮。

| 当前步骤 | 可以进行的操作 |
| --- | --- |
| 发现新版本 | 立即更新、稍后提醒、跳过此版本 |
| 下载中 | 取消下载；同一界面只显示一个取消按钮 |
| 下载完成 | 继续安装、稍后安装 |
| 下载失败 | 重新下载、稍后重试 |

下载时会显示更新内容、当前下载渠道、百分比和已下载大小；渠道自动切换时界面会随之更新，重定向后显示实际提供下载的渠道。下载源失败时会尽量保留已下载的数据并换线续传；点击取消则会停止当前请求并清理临时文件。服务器没有提供文件总大小时，显示实际已下载大小和等待动画，不显示猜测的百分比。下载完成并校验通过后，交给 Android 系统确认安装；如果系统要求安装权限，请授权后返回 khLink 继续安装。

“稍后提醒”会收起本次提示；“跳过此版本”会记住这个版本，发布更高版本后再提醒。安装更新会保留登录信息和聊天记录。

Android 0.1.247 起，设置中的“检查更新”始终检查是否有比当前安装版本更新的版本，不受“稍后提醒”或“跳过此版本”影响。这两个选择只控制自动提醒；手动检查不会清掉它们。旧版本可能把被隐藏的更新误报为“当前已是最新版”，可从官网下载正式 APK 覆盖安装，保留登录和聊天记录，不要卸载旧版。

按钮纵向排列，文字区域在大字体或较小屏幕上可以滚动。主题配色沿用应用设置，不因更新弹窗改变。
